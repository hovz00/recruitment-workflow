# 仓库更名与工作流修复

对外仓库固定为 `https://github.com/hovz00/recruitment-workflow`。本次基于替换后的仓库提交 `f337a7bfe3b26f5d8a918c270bc66304186937f0` 修复，保留其本地恢复、确认写回和候选人档案能力。

## 已处理

- 首页、工具入口和包名统一为 Recruitment Workflow，修正旧看板文件名引用。
- 限制岗位、提案和候选人 ID 的路径形式，阻止路径越界和符号链接写入。
- 确认前核对当前岗位、最新提案、提案内容和台账 / 流程版本；拒绝覆盖已有提案编号。
- 新增候选人只使用整行空白的位置，必填来源、收取日期、阶段和状态；更新必须带修改前值。
- 保留已确认岗位文档，默认模板标记草稿；初始化加锁，避免并发失败删除已创建岗位。
- 待办包括中间阶段通过和 Offer 待入职；本轮反馈不再由其他轮次的旧摘要抵消。
- 新增可重复运行的旧岗位迁移，保留文档、候选人行和备份。
- 重复同步仅更新上下文中的同步元数据行，不删除后续业务事实。
- 台账追加动态阶段日期、通过日期和 Offer 日期，保留自定义阶段 SLA。
- 更新正式复盘模板，支持自动载入和手动上传；标准导出统一为第一行表头的 XLSX / CSV。
- 默认预览 / 导出移除直接标识和自由文本，明确内部模式及候选人明细的隐私边界。
- 停用旧的直接写入 CLI，候选人操作统一经确认写回；保留旧转换函数供兼容测试使用。

## 兼容性

`.recruitment-agent/`、`AGENT_PROTOCOL.md` 和工具入口文件路径保留，避免因品牌改名丢失本地状态。旧提案没有本次新增的预览校验记录，需要重新生成预览，不能直接执行。

以前使用固定约面日期的台账不会自动补造阶段历史；迁移只增加空字段。看板默认不包含姓名、公司和备注，内部明细需求应显式选择 `internal`。

既有 HTML 在同步时从固定模板重建，旧文件保留 `.bak`。真实岗位目录和数据不纳入代码提交。历史设计文档记录当时方案，当前行为以 README、运行协议及复盘数据说明为准。

## 验证方式

`npm test` 验证脚本和数据回归；`npm run test:browser` 在真实浏览器中检查预览、XLSX 和 CSV 导入的一致性。GitHub Actions 运行两组测试。浏览器用例全部使用虚构记录。
