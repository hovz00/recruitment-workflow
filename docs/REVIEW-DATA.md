# 复盘数据与上传约定

候选人台账是操作事实源；HTML、XLSX 和 CSV 都由 `readReviewData` 的同一套字段映射生成。看板的手动上传仅改变当前浏览器中的分析，刷新会恢复文件内嵌数据，修改台账后需重新同步。

## 字段

| 字段 | 来源与用途 |
| --- | --- |
| 主阶段、阶段状态 | 使用岗位流程的 `id-name` 和进行中 / 通过 / 终止 |
| 终止原因 | 终止必填；默认导出保留标准枚举，非标准自由文本归为其他待说明 |
| 简历收取时间、简历来源 | 新增候选人必填；收取日期用于看板的月度 / 周度批次分析 |
| 岗位名称 | 同步 / 导出命令指定的岗位 |
| 候选人姓名、当前公司、备注信息 | 内部模式对应台账姓名、公司、备注；默认使用序号并清空公司和备注 |
| Offer接受日期、预计入职日期 | 只填已确认的接受事实和预计入职安排 |
| `0-阶段名日期` 等 | 实际进入该阶段的日期；名称和编号来自 PIPELINE.json |
| `0-阶段名通过日期` 等 | 实际通过该阶段的日期 |

保留原台账的前 43 列位置，新增日期列追加在后面。原有 `一面日期`、`二面日期` 等属于约面安排，不自动复制为实际进入日期。已确认未来面试时间可以推进操作状态，但不得把未来约面日期当作已发生的历史节点。

阶段 `id` 从 0 连续编号，名称不能重复。可配置 `slaDays` 为 1–90 的整数；未设置时使用看板内置默认值。实际日期未知时留空，不猜测，不填今天，不根据当前阶段编造之前各轮的日期。

## 预览

```bash
node workflow/scripts/sync-dashboard-data.mjs --ledger "workflow/roles/岗位名称/candidate-ledger.xlsx" --dashboard "workflow/roles/岗位名称/招聘数据复盘.html" --role "岗位名称" --context "workflow/roles/岗位名称/CONTEXT.md"
```

同步使用仓库内固定的正式模板重建页面，前一个页面保留为 `.bak`。若曾手动修改岗位 HTML 的样式，请先另存；长期界面调整应修改项目模板。

## 标准导出

```bash
node workflow/scripts/export-review-data.mjs --ledger "workflow/roles/岗位名称/candidate-ledger.xlsx" --role "岗位名称" --out "workflow/roles/岗位名称/exports"
```

导出为只有一个数据工作表、第一行即表头的 XLSX，以及带 UTF-8 BOM 的 CSV。两种文件内容一致，任选一个上传。CSV 对可能被表格软件当作公式的文本加单引号保护。缺少阶段、状态、来源或收取日期，或终止缺原因时，导出会报错要求补齐。

独立看板位于 [recruitment-review](https://github.com/hovz00/recruitment-review)。先按 `导入说明.md` 配置阶段名称、顺序与 SLA，再上传标准导出文件。**不要直接上传 `candidate-ledger.xlsx`**：它的表头在第 3 行，而且包含状态字典、复盘口径和选项配置，旧版解析器可能把配置表当作候选人数据。

## 隐私和口径限制

默认 `redacted` 模式会移除直接标识和自由文本；非标准来源归为“其他”。候选人序号仅用于本次导出，不是跨导出的稳定 ID。日期、岗位、来源等组合仍有再识别可能，因此文件不是完全匿名数据，也不是纯聚合报表。公司和文本相关分析在此模式下不完整。

只有明确授权内部查看明细时才使用 `--privacy internal`。这会导出姓名、公司和备注。原始 Excel、候选人档案、备份始终可能包含个人信息，应保存在自己的受控工作区。

漏斗依据当前阶段推导到达情况；月度 / 周度以简历收取批次观察转化，不等同于期间发生的面试场次数。阶段历史和 SLA 的可信度依赖已确认的真实日期。缺失日期会限制时效分析。
