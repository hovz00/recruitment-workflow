# 岗位确认与数据校验

## 岗位标准确认

先展示完整岗位标准、流程和适用范围。招聘者明确确认后，AI 保存文档，并记录版本、确认人和依据。不得根据模板版本、历史对话猜测或自行生成招聘者的确认。

初始化接受 `--documents <文档映射.json>` 和 `--confirmation <确认信息.json>`。确认信息字段为 `version`、`confirmedBy`、`evidence`，均为非空单行文本；只有收到招聘者确认才传入。未传确认信息时可建立草稿工作区，但不能写入候选人。提供确认信息时，岗位标准和上下文必须是完整文档，不能仍有草稿标记或模板占位符。

旧岗位先选择为本会话当前岗位，检查 `ROLE_STANDARD.md`、`CONTEXT.md` 和 `PIPELINE.json`。补齐必要的台账字段后，可使用迁移脚本保留原数据；迁移不等于标准确认。招聘者核对并确认后执行（会话编号使用 `create-session.mjs` 的实际返回值）：

```bash
node workflow/scripts/confirm-role-standard.mjs --root . --session "返回的会话编号" --role "岗位名称" --version "已确认版本" --confirmed-by "实际确认人" --evidence "实际确认依据"
```

`ROLE_CONFIRMATION.json` 保存标准和流程的内容摘要，`ACTION_LOG.md` 追加确认记录。修改岗位标准或流程后，需再次核对并确认，再生成候选人预览；先前的待确认提案不再适用。常规候选人跟进追加到上下文或操作日志，不会因此使岗位确认失效。

确认记录是本地流程控制，不是账号认证或防篡改权限系统。拥有文件写入权限的人仍需遵守招聘确认协议。

## 同名但不同人

同名时先核对身份；是同一人则使用原 ID 更新。确认是不同人时，在新建候选人的提案中提供 `identityResolution`：

- `confirmedDistinct`：必须是布尔值 `true`。
- `matchedCandidateIds`：列出本岗位所有已匹配的同名候选人 ID，必须与台账完全一致。
- `reason`：记录如何核实为不同人的依据，不能为空。

这些信息属于待确认提案的一部分，会写入候选人档案和操作日志。不能以统一打开的“允许重名”选项跳过核实，也不能复用已有 ID 或档案。如果同名旧记录缺 ID，先补齐身份，再生成新预览。

## 自定义面试

阶段使用 `kind: "interview"` 标记为面试；`kind: "process"` 明确表示非面试环节。面试可通过 `appointmentField` 选择原有“一面日期、二面日期、三面日期、HRBP日期、决策会日期”之一，或使用本阶段的 `编号-阶段名预约日期`。不指定字段时，显式面试阶段使用后者。不同面试阶段不能共用一个预约字段。

例如“案例答辩”阶段应配置为面试，并使用对应的预约日期字段。已有岗位补充字段后，运行迁移脚本把缺失列追加到台账；单纯新增面试元数据不需要修改阶段名称或顺序。涉及改名和阶段顺序变化时，先人工核对历史列与流程映射，不能直接丢弃历史日期。

快照根据当前阶段的预约日期及 `[编号-阶段名]` 反馈标签识别待反馈。旧配置的一面、二面、三面、HRBP、决策会仍保留原字段映射；其他自定义面试必须明确配置类型。预约列只用于跟进，不当作实际阶段历史导出到漏斗。

## 数据要求

- 来源、收取日期、主阶段、阶段状态始终必填；终止必须有原因，恢复时明确清空旧原因。
- 能力证据得分为 0–10，证据覆盖率为 0–100；支持数字及纯数字文本。空值表示未知，0 是明确的零值；不接受百分号、单位、布尔值和无穷值。
- 日期为有效 `YYYY-MM-DD` 或 Excel 日期。收取日期、实际进入/通过日期和 Offer 接受日期不能是未来日期，历史日期不能早于收件，也不能与已知前序阶段矛盾；允许同日推进。
- 固定约面或自定义预约、下次跟进、预计入职允许在未来。预计入职不能早于已确认的 Offer 接受日期。
- 未知历史日期可以留空，不能为了通过检查而编造。补录历史或修正错误日期时，按证据修正相关字段，使整条记录一致。

确认写回校验修改后的完整记录；同步和导出校验去标识化之前的完整台账。因此旧行缺少必填项或有矛盾日期也会被指出，不能默默丢弃。写回过程中发现其他行不合法时会回滚本次变更，修复错误后重新预览。原有材料和错误行均保留。

## 看板上传

上传 `export-review-data.mjs` 生成的标准 XLSX 或 CSV。操作台账的说明行、配置表、字典表不是候选人数据，上传端会识别并拒绝；有效的多岗位数据表可同时导入。上传失败不替换旧数据、分析结果或阶段配置。手动上传仍只影响当前浏览器预览，不写回业务台账。
