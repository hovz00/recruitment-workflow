# 简历评估提示词

开始前读取 `AGENTS.md`、当前岗位的 `ROLE_STANDARD.md`、`PIPELINE.json`、`SCORING_RULES.json`、`ROLE_CONFIRMATION.json`、`candidate-ledger.xlsx` 和同岗位已有候选人档案及评估记录。仅处理已获得授权的简历文本或 PDF 提取文本。执行约定见 [评分规则与证据复核](../../docs/SCORING-CONSISTENCY.md)。

## 工作步骤

1. 先检查岗位标准、流程和评分规则是否已完整确认且摘要有效；未确认时仅做结构化整理，首行标明“待确认评分规则”，不给临时得分。旧岗位可继续不涉及评分的跟踪，新增或改分前必须补齐规则。
2. 先用姓名、当前公司、当前岗位和教育经历提示可能重复记录；不能确定时请招聘者确认，不要擅自合并。
3. 检查台账必填流程信息：**简历来源**和**简历收取时间**。材料或用户输入未提供时，先只问一个问题补齐缺失字段；来源可选内部人才库、员工推荐、招聘平台、猎头、官网投递、活动/社群或其他，收取时间使用 `YYYY-MM-DD`。未确认前不得编造，也不得写入台账。
4. 按以下证据卡要求生成完整评估输入，用 `evaluate-resume.mjs --root <根目录> --input <assessment.json> --session <会话编号>` 校验并计算。输出必须**结论先行**：第一行为 `姓名｜建议：{{脚本返回的复核建议}}｜能力证据得分：x/10｜证据覆盖率：x%`。以脚本结果为准，建议不表示流程决策。
5. 紧接第一行写不超过三条的整体判断；所有尚缺或无法确认的信息必须以 `**待核实**：...` 的粗体格式呈现。
6. 再输出结构化简历：姓名、年龄、学历、总工作年限、对口岗位年限、对口项目年限、当前公司/岗位、Base、关键经历、项目、量化成果与信息缺口。没有写明的字段填“待验证”。
7. 按评分规则的全部 3–5 个维度生成一张证据卡。每维必须包含：岗位要求、原文摘录与脚本定位的来源行、证据等级、规则中已有的准确档位分值、已具备信息、信息缺口、电话核验问题。已具备信息优先写明行动、范围、结果和本人责任；禁止把推断写成事实、编造行号或在两个档位之间自由给分。
8. 单独核对年龄和年限资格规则：只按 `ROLE_STANDARD.md` 中已确认的范围与口径提示“匹配 / 待核实 / 待人工确认”；不自动终止流程。
9. 生成候选人电话沟通问题，优先问证据缺口、动机、Base、薪资、职级、Offer 与到岗时间。
10. 生成候选人提案：`assessment` 为评估命令返回的完整 `input` 加上 `rulesDigest: result.rulesDigest`，同时提交等于脚本结果的 `能力证据得分` 和 `证据覆盖率`。展示字段差异、依据与复核理由，经招聘者确认后用确认写回脚本更新台账、档案及 `candidates/<ID>.assessment.json`，不得直接编辑台账代替确认流程。

## 固定输出结构

### 结论先行

```text
{{姓名}}｜建议：{{脚本返回的人工复核或补充证据建议}}｜能力证据得分：{{x/10}}｜证据覆盖率：{{x%}}
整体判断：{{最多三条、只基于已出现的证据}}
**待核实**：{{缺口1；缺口2}}
```

### 结构化简历

使用字段表格呈现，并标记每个字段的来源或“待验证”。

### 候选人证据卡

证据等级只使用：`直接证据`、`间接证据`、`暂无证据`。

- 直接证据：行动、本人责任与结果明确；
- 间接证据：经历相关，但范围、责任或结果不完整；
- 暂无证据：材料未体现，作为待核验信息，不等同于不匹配。

分值只能选用当前岗位已确认的档位，不使用通用分段替代。暂无证据必须为 `score: 0`、`quote: ""`；其他等级提供可在完整 `resumeText` 中找到的原文摘录和理由。只有 `confirmed` 校准样例可供参照，`pending` 样例不参与评分。

能力证据得分 = Σ(各维档位分值 × 权重) / 100；证据覆盖率 = (直接证据维度数 + 间接证据维度数) / 全部维度数 × 100。均保留一位小数。不能删去缺失维度或重新归一化权重；0 分描述当前证据缺失，不是能力否定。

评估输入须包含候选人 ID/姓名、完整 `resumeText`、匹配岗位配置的 `model` / `promptVersion`、全部维度 `{id, grade, score, quote, rationale}`，以及必要的 `reviewReasons`。只读评估命令向标准输出返回 JSON，不保存结果；相同候选人、简历、规则和模型配置已有确认记录时复用该记录，不会因新提交维度判断或核实理由就替换历史。确需同输入重评时填写 `reevaluationReason`，展示变化与理由后重新确认。规则变更不自动重评历史；模型别名也不保证后端固定。复核阈值比较使用未舍入值。

每一维以表格输出：`岗位要求`、`简历原文与来源位置`、`证据等级`、`证据强度（0–10）`、`已具备信息`、`信息缺口`、`电话核验问题`。只覆盖 3–5 个核心能力维度；年龄、学历和工作年限放在资格提示中单列。

### 台账拟写回内容

先展示待写入的候选人台账字段和候选人 ID；等待人工确认后再写回。台账不应保存简历原文，只保存结构化事实和简短证据摘要。
