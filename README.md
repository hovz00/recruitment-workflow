# Recruitment Workflow

[![Tests](https://github.com/hovz00/recruitment-workflow/actions/workflows/test.yml/badge.svg)](https://github.com/hovz00/recruitment-workflow/actions/workflows/test.yml)

一套由招聘者确认、AI 工具协助执行的本地招聘工作流。从 JD 和初步画像开始，连接需求澄清、寻源、简历证据评估、电话沟通、面试安排与反馈、Offer / 入职跟进和数据复盘。

适用于 Codex、Claude Code、Cursor 等能读取本地文件、执行命令的工具。岗位规则用 Markdown 保存，候选人流程以 Excel 为唯一事实源；使用现有 AI 工具即可运行，无需额外接入模型 API、配置数据库或部署服务器。

## 开始使用

```bash
git clone https://github.com/hovz00/recruitment-workflow.git
cd recruitment-workflow
npm ci
npm test
```

需要 Node.js 20+。在 AI 工具中打开仓库后，可以直接说：

```text
新建 AI 产品经理岗位。这是 JD 和初步画像：……
先帮我澄清业务目标、核心能力、可协商条件和面试流程。

评估这份简历；来源是员工推荐，收取日期是 2026-09-01。

候选人 C-001 一面通过，待安排二面。先展示更新预览。

同步当前岗位复盘看板，并打开预览。

导出当前岗位的复盘数据，用于上传到 recruitment-review。
```

工具通过 [统一运行协议](workflow/AGENT_PROTOCOL.md) 恢复当前岗位、调用相关 Skill、展示变更预览，再按你的确认更新文件。候选人变更会校验岗位、ID、流程和修改前值，同时写入档案、操作日志与看板；失败时恢复备份。

岗位标准和流程需要明确确认，确认版本、确认人、依据及文档摘要保存在 `ROLE_CONFIRMATION.json`。草稿或未经确认的旧岗位不能直接写入候选人；标准或流程变化后，旧预览失效，需核对并重新确认。具体步骤见 [岗位确认与数据校验](docs/WORKFLOW-GUARDS.md)。

## 招聘全流程

| 环节 | 主要产物 | 招聘者需要确认 |
| --- | --- | --- |
| JD 与画像澄清 | 岗位标准、证据口径、待核实项、流程配置 | 业务目标、核心要求、可协商项、阶段顺序 |
| 寻源准备 | 公司 / Title / 项目线索、检索式、关键词迭代 | 寻源范围和筛选依据 |
| 简历评估 | 直接 / 间接证据、缺口、电话验证问题 | 来源、收取日期、重复候选人、评估结论 |
| 电话沟通 | 动机、Base、期望、到岗时间、沟通纪要 | 哪些是事实、哪些仍需验证 |
| 约面与面试反馈 | 约面草稿、约定日期、本轮反馈、下一步 | 面试安排与阶段通过 / 终止结论 |
| Offer 与入职 | 接受日期、预计入职日期、跟进待办 | 接受事实、入职事实和流程状态 |
| 招聘复盘 | 即时预览 HTML、标准 XLSX / CSV | 数据质量、反馈适用范围、是否修改策略 |

“一面通过，待安排二面”保留为“一面｜通过”，下一步写“安排二面”，仍计入待跟进。二面时间已确认后进入“二面｜进行中”。约定面试日期与实际进入 / 通过阶段的日期分别记录；未知历史日期留空。最后一个阶段通过才表示流程完成。

## 多岗位管理与简历输入

每个岗位在 `workflow/roles/` 下拥有独立目录，分别保存岗位标准、流程配置、候选人台账、证据档案和复盘看板。初始化时自动创建目录，每个岗位默认预留 1,000 条候选人记录，可通过 `--capacity` 指定初始容量。

每个 AI 对话使用独立会话编号，分别保存当前岗位和最新预览。操作前可直接说“切换到 AI 产品经理岗位”；AI 会为该对话选择岗位，其他对话的选择保持不变。写入通过工作区锁串行完成，遇到占用最多等待 5 秒；同一台账已被另一对话更新时，旧预览需要重新生成。会话设置由 AI 按协议管理，使用步骤见 [多对话与跨岗位人才管理](docs/SESSIONS-AND-TALENT.md)。

原始简历建议保存在对应岗位目录内，例如 `workflow/roles/AI产品经理/resumes/`，再向 AI 指明文件路径、来源和收取日期。`resumes/` 可按需自行建立，`candidates/` 用于保存逐人证据与互动记录。也可使用 AI 客户端支持的对话附件，但原件归档需要另行安排。简历读取依赖所用工具的文件处理能力，项目不内置 OCR 或文件夹自动导入服务。

同名候选人先查重。核对后确认是不同人，可以使用各自的唯一 ID，并把匹配 ID 和核实依据写入同名处理预览；不需要修改真实姓名。同一 ID、大小写别名或核实范围不一致仍会被拒绝。

新增预览会提示其他岗位的同名申请。明确核实为同一人后，可通过身份关联提案把多个岗位申请关联到统一人才编号，查询各岗位进度；也可在发现误关联后确认解除。跨岗推荐先按目标岗位标准建立独立申请，再关联身份。关联不会复制评分、面试结论或修改原岗位状态，姓名相同也不会自动合并。人才查询同时显示申请数和按已确认关联去重的人数；复盘看板继续按岗位申请记录统计。

来源、收取日期、阶段和状态在新增、更新、同步及导出时都要完整。得分允许 0–10，覆盖率允许 0–100，空值表示未知。实际阶段日期须符合已知时间顺序；未来约面、跟进和预计入职单独记录。自定义面试如“案例答辩”通过流程中的 `kind: "interview"` 和预约日期字段识别待反馈，不依赖面试名称。

## 即时预览与手动上传

通过确认写回脚本更新候选人后，会从台账重建岗位目录内的 `招聘数据复盘.html`。可以直接让 AI “同步当前岗位看板并打开预览”，无需手动上传台账。页面已打开时，刷新即可查看同步后的数据；当前采用按操作同步的方式，不持续监听 Excel 文件或自动刷新浏览器。

看板也支持手动上传其他数据做临时分析，上传不会反向覆盖台账。项目内置正式看板模板，按岗位流程加载阶段名称、顺序、SLA 和候选人数据。

导出到独立的 [recruitment-review](https://github.com/hovz00/recruitment-review) 看板：

```bash
node workflow/scripts/export-review-data.mjs --ledger "workflow/roles/岗位名称/candidate-ledger.xlsx" --role "岗位名称" --out "workflow/roles/岗位名称/exports"
```

产物为 `recruitment-review-data.xlsx`、同内容 CSV 和 `导入说明.md`。按照说明配置阶段与 SLA 后，上传其中一个数据文件。导出包含第一行标准表头、动态阶段日期及 Offer 日期，避免原始台账的说明行、配置表被误读。

看板会拒绝操作台账、配置表和不合法表头。错误文件、取消文件选择或取消字段映射会保留上一份有效分析；通过上传向导临时修改的阶段配置也会恢复。

默认导出和预览移除姓名、候选人 ID、公司、自由文本，姓名替换为本次导出的序号。**仍含候选人级流程明细，并非纯聚合或完全匿名。** 明确需要内部明细时，可给同步 / 导出命令添加 `--privacy internal`；该模式包含个人信息。

## 长期事实源

```text
workflow/roles/<岗位名称>/
├── CONTEXT.md              # 已确认事实、待确认问题与下一步
├── ROLE_STANDARD.md        # 版本化岗位标准
├── ROLE_CONFIRMATION.json  # 明确确认的版本、人员、依据和文档摘要
├── SOURCING_STRATEGY.md    # 寻源策略
├── KEYWORD_ITERATIONS.md   # 关键词与命中反馈
├── FEEDBACK_ITERATIONS.md  # 反馈校准记录
├── PIPELINE.json           # 阶段顺序、状态、SLA 与面试预约字段
├── candidate-ledger.xlsx   # 候选人流程事实源
├── candidates/             # 逐人证据与更新档案
├── ACTION_LOG.md           # 确认写回日志
└── 招聘数据复盘.html        # 本地预览
```

`.recruitment-agent/` 保存会话、待确认提案、人才身份关联索引及写入备份；`AGENT_PROTOCOL.md` 定义统一运行规则。真实岗位、候选人、提案、身份关联、备份及默认导出目录被 `.gitignore` 排除。聊天记录用于临时交流，长期事实以岗位文件、台账、身份关联索引和操作日志为准。未传会话编号的旧脚本仍使用原有全局当前岗位，适合单对话兼容使用。

## 能力边界与验证

AI 整理证据、生成草稿和提出建议；招聘者决定标准、例外及流程结论。项目不抓取招聘平台，不自动发送消息或日历邀请，不自动淘汰、录用或联系候选人。材料缺失标为“待核实”。

自动化测试覆盖岗位恢复、确认写回、回滚、迁移和复盘字段；浏览器测试验证即时预览与 XLSX / CSV 导入：

```bash
npx playwright install chromium
npm run test:browser
```
