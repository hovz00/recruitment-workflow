# Recruitment workflow

一个可在 Codex、Claude Code、Cursor 等本地 AI 编程工具中通过自然语言运行的招聘协作 Agent。它把岗位澄清、寻源、简历证据、电话沟通、面试反馈、候选人台账和招聘复盘连接为一条可恢复、可追溯的本地工作链路。

## 用户如何使用

在支持本地文件读取与命令执行的 AI 工具中打开本项目后，直接说：

```text
继续上次的招聘。
新建一个 AI 产品经理岗位，这是 JD：……
评估刚上传的简历。
张某一面通过，待安排二面。
同步看板并复盘当前岗位。
```

工具入口会引导 AI 自动读取 `workflow/AGENT_PROTOCOL.md`。用户无需指定文件路径、Excel 字段或 Node 命令；涉及台账、候选人档案、流程状态和岗位规则的修改，Agent 会先展示自然语言变更预览，获得确认后再写入。

## 长期状态

聊天记录只是临时上下文。长期事实保存在本地工作区：

```text
workflow/roles/<岗位名称>/
├── CONTEXT.md              # 已确认岗位规则与下一步
├── ROLE_STANDARD.md        # 岗位标准和证据口径
├── SOURCING_STRATEGY.md    # 搜寻策略
├── PIPELINE.json           # 岗位专属流程阶段和顺序
├── candidate-ledger.xlsx   # 候选人流程唯一事实源
├── candidates/             # 逐人简历证据、电话和面试档案
├── ACTION_LOG.md           # 仅追加的确认写回日志
└── 招聘数据复盘.html        # 台账同步后的复盘看板

.recruitment-agent/
├── current-role.json       # 当前岗位
├── pending-actions/        # 待确认变更提案
└── backups/                # 执行期间的本地备份
```

真实岗位与候选人数据、待确认提案和备份均被 `.gitignore` 排除，不会默认进入 GitHub。

## 工作方式

1. Agent 读取统一协议与当前岗位事实源，识别“新建岗位、评估简历、电话沟通、面试反馈、进展更新、复盘”等任务。
2. AI 使用内置 Skill 整理材料、提取证据、提出待核实项和生成草稿。
3. 修改前生成提案，展示岗位、候选人、修改前后与依据。
4. 招聘者明确确认后，本地脚本校验流程、字段和修改前值，再更新 Excel、Markdown、日志与复盘看板。
5. 每次新会话可从当前岗位、台账、上下文和操作日志恢复工作，不依赖上一段聊天历史。

阶段规则：主阶段记录候选人已经实际到达的节点；阶段状态仅为“进行中、通过、终止”。例如“一面通过，待安排二面”保留为“一面｜通过”，下一步动作写“安排二面”；二面时间已确认后才进入“二面｜进行中”。

## 本地脚本

这些脚本由 Agent 调用；普通用户不需要手动运行。

- `initialize-role-workspace.mjs`：在岗位标准和流程确认后创建岗位工作区、台账和复盘看板。
- `set-current-role.mjs`：切换当前岗位。
- `get-role-snapshot.mjs`：恢复岗位状态与待办。
- `create-pending-action.mjs`：保存待确认的内部变更提案。
- `apply-confirmed-action.mjs`：确认后校验、写回、记录日志并同步看板。

运行环境：Node.js 18+。

```bash
npm install
npm test
```

## 边界

- 不接入模型 API、云数据库、登录或独立网页聊天界面。
- 不抓取招聘平台，不自动打招呼、联系、约面、拒绝、淘汰或录用候选人。
- AI 负责整理证据和生成草稿；招聘者负责岗位标准、例外判断及所有不可逆决策。
- 简历中没有明确出现的信息标记为“待核实”，不由模型补充或作为隐性扣分。

详细运行规则见 [统一 Agent 协议](workflow/AGENT_PROTOCOL.md)。
